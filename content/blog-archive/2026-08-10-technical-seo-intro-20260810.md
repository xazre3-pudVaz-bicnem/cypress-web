# テクニカルSEOの基礎：Core Web Vitalsとサイト構造の最適化

「良いコンテンツを書いているのに、なぜか検索順位が上がらない」という悩みを抱える方は少なくありません。その原因の一つとして見落とされがちなのが、テクニカルSEOの問題です。

Googleは検索順位を決定する際に、コンテンツの質だけでなく、サイトの技術的な品質も評価しています。ページの読み込み速度、モバイル対応、サイト構造——これらが整っていなければ、どれだけ良い記事を書いても上位表示は難しくなります。

この記事では、中小企業の担当者が今日から取り組めるテクニカルSEOの具体的な施策を解説します。

---

## テクニカルSEOとは何か、なぜ今重要なのか

テクニカルSEOとは、検索エンジンがサイトを正しくクロール・インデックスできるよう、技術的な観点からサイトを最適化する取り組みです。コンテンツSEO（記事の質や量）とは異なる領域ですが、両者は車の両輪のような関係にあります。

Googleは2021年にCore Web Vitalsをランキング要因として正式に組み込みました。それ以降、技術的な品質はSEO戦略において無視できない要素になっています。特に競合が多いキーワードでは、コンテンツの質が同程度の場合にテクニカルな優位性が差を生むケースが増えています。

中小企業のサイトの場合、大企業ほどの予算やエンジニアリソースがない分、基礎的な項目を着実に押さえることが重要です。

---

## Core Web Vitalsの3つの指標を理解する

Core Web Vitalsは、ユーザー体験を測定するための3つの指標で構成されています。Google Search Consoleの「ウェブに関する主な指標」レポートで現在の状況を確認できます。

### LCP（Largest Contentful Paint）：読み込みパフォーマンス

ページ内で最も大きな要素（多くの場合、メインビジュアルの画像や大きな見出し）が表示されるまでの時間です。Googleの推奨値は**2.5秒以内**です。

LCPが遅い主な原因として次の点が挙げられます。

- 画像ファイルのサイズが大きすぎる（最も多い原因）
- サーバーの応答速度が遅い
- レンダリングを妨げるJavaScriptやCSSの読み込み

対策の優先順位としては、まず画像の最適化から始めるのが効率的です。WebP形式への変換、適切なサイズへのリサイズ、遅延読み込み（Lazy Load）の設定を行うだけでも改善が見込めます。

### FID / INP（インタラクティビティ）：操作への反応速度

FID（First Input Delay）は2024年3月にINP（Interaction to Next Paint）に置き換わりました。ユーザーがボタンをクリックしたりフォームに入力したりした際に、サイトがどれだけ素早く反応するかを測定します。推奨値は**200ミリ秒以内**です。

重いJavaScriptの処理が主な原因となることが多く、不要なプラグインやサードパーティスクリプトの見直しが有効です。

### CLS（Cumulative Layout Shift）：視覚的な安定性

ページ読み込み中にコンテンツが突然ずれる現象（レイアウトシフト）を測定します。「記事を読もうとしたら広告が表示されてページが動いた」という経験がある方も多いでしょう。推奨値は**0.1以下**です。

対策としては、画像や動画の縦横比をCSSで明示的に指定する、広告スペースを事前に確保しておく、などが効果的です。

## サイト構造の最適化：クロールビリティを高める

いくら優れたコンテンツがあっても、Googleのクローラーがページを発見・理解できなければ意味がありません。サイト構造の整備は、テクニカルSEOの根幹とも言える部分です。

### XMLサイトマップとrobots.txtの確認

XMLサイトマップは、サイト内の重要なページをGoogleに伝えるための地図のような役割を持ちます。WordPressであればプラグインで自動生成できますが、以下の点を確認してください。

- インデックスさせたくないページ（管理画面、検索結果ページなど）が含まれていないか
- 定期的に更新・送信されているか（Search Consoleから送信）

robots.txtは、クローラーにアクセスを許可・拒否するページを指示するファイルです。誤った設定で重要なページがクロールされていないケースが意外と多く見られます。`https://yoursite.com/robots.txt`でアクセスして内容を確認しましょう。

### 内部リンク構造の整備

サイト内のページ同士を結ぶ内部リンクは、クローラーの巡回経路であると同時に、ページの重要度を伝える役割も担います。

チェックすべきポイントは以下の通りです。

- どこからもリンクされていない「孤立ページ」が存在しないか
- 重要なページほど上位の階層（トップページからのクリック数が少ない場所）にあるか
- アンカーテキストが「こちら」「詳細」など文脈のわからない表現になっていないか

### 重複コンテンツとcanonicalタグ

同じような内容のページが複数存在すると、Googleはどちらを評価すべきか判断できずに評価が分散してしまいます。ECサイトのカラー別商品ページや、パラメータ付きURLなどでよく発生します。

正規のURLを示すcanonicalタグをHTMLのhead内に設定することで、この問題に対処できます。

## 構造化データでリッチリザルトを狙う

構造化データとは、ページの内容をGoogleが理解しやすいように構造化されたマークアップで記述したものです。適切に設定すると、検索結果に星評価・FAQの展開・パンくずリストなどが表示される「リッチリザルト」として表示される場合があります。

よく使われる構造化データの種類：

| タイプ | 適したページ | 期待できる表示 |
|---|---|---|
| Article | ブログ記事・ニュース | 画像付き表示 |
| FAQ | よくある質問ページ | Q&Aの展開表示 |
| LocalBusiness | 店舗・企業情報 | 営業時間・電話番号 |
| BreadcrumbList | 全ページ | パンくずリスト |

JSON-LD形式でHTMLのhead内に記述するのが現在の標準的な方法です。WordPressの場合はYoast SEOなどのプラグインが自動生成してくれますが、内容が正しいかどうかはGoogle提供の「リッチリザルトテスト」で確認してください。

## 今日から始めるテクニカルSEO改善の優先順位

テクニカルSEOには多くの項目がありますが、すべてを一度に対応しようとすると途方もない作業量になります。以下の順序で優先度を判断すると効率的です。

**最優先で確認すべき項目**

1. Google Search Consoleで「カバレッジエラー」「ウェブに関する主な指標」にエラーや警告が出ていないか
2. PageSpeed Insightsでモバイルのスコアを確認し、LCPとCLSの改善点を把握する
3. サイトがHTTPS化されているか
4. モバイルフレンドリーテストでエラーが出ていないか

これらに問題がなければ、構造化データの整備、内部リンクの見直しと順番に進めていくとよいでしょう。

---

## まとめ

テクニカルSEOは一度対応すれば終わりというものではなく、Googleのアルゴリズム変更やサイトの更新に合わせて継続的に見直す必要があります。とはいえ、基礎的な項目を押さえるだけでも検索エンジンからの評価は変わってきます。

まずはSearch ConsoleとPageSpeed Insightsで現状を把握するところから始めてみてください。問題の所在が明確になれば、対応の道筋も見えてきます。

---

テクニカルSEOは「何が問題なのか特定する」段階が最も難しく、そこで多くの担当者が手を止めてしまいます。株式会社サイプレスでは、サイトの技術的な課題を診断した上で、SEO対策・サイト改善を一緒に進めるサポートを提供しています。「自社サイトのどこに問題があるかわからない」という段階からでも、お気軽にご相談ください。
