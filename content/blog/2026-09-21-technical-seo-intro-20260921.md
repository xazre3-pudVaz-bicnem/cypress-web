# テクニカルSEOの基礎：Core Web VitalsとWebサイト構造の最適化

「コンテンツはしっかり書いているのに、なぜか上位表示されない」という悩みを持つ担当者の方は多いです。その原因の一つとして見落とされがちなのが、**テクニカルSEO**の不足です。

テクニカルSEOとは、コンテンツの質とは別に、サイトの技術的な土台を整える施策のことを指します。Googleのクローラーがサイトを正しく認識できるか、ユーザーが快適にページを閲覧できるか、といった要素が評価に影響します。

本記事では、特に重要度が増している**Core Web Vitals**と**サイト構造の最適化**について、中小企業の担当者でも取り組みやすい形で解説します。

---

## Core Web Vitalsとは何か？なぜ重要なのか

Core Web Vitalsは、Googleが2021年に検索ランキングの評価要素として正式導入した「ユーザー体験の指標」です。現在は以下の3つの指標が中心になっています。

**LCP（Largest Contentful Paint）：ページの主要コンテンツが表示されるまでの時間**
- 良好：2.5秒以内
- 改善が必要：2.5〜4.0秒
- 不良：4.0秒超

**INP（Interaction to Next Paint）：ユーザーの操作に対するページの応答速度**
- 良好：200ミリ秒以内
- 改善が必要：200〜500ミリ秒
- 不良：500ミリ秒超

**CLS（Cumulative Layout Shift）：ページレイアウトのずれ具合**
- 良好：0.1以下
- 改善が必要：0.1〜0.25
- 不良：0.25超

これらの数値が「良好」の範囲にあると、Googleのランキングにポジティブな影響を与えるとされています。逆に「不良」の状態が続くと、検索順位の面だけでなく、直帰率の上昇にもつながる可能性があります。

自社サイトの現状は、**Google Search Console**の「ウェブに関する主な指標」レポートや、**PageSpeed Insights**（https://pagespeed.web.dev/）で無料確認できます。まずは計測から始めましょう。

---

## サイト速度を改善するための具体的施策

Core Web Vitalsの数値改善に直結するのが、**ページ読み込み速度の最適化**です。特にLCPのスコアは、以下の対応で改善が見込めます。

### 画像の最適化

多くのサイトで速度低下の主因となるのが、最適化されていない画像ファイルです。

- **フォーマットの変換**：JPEGやPNGをWebPやAVIFに変換する。ファイルサイズを大幅に削減できます。
- **適切なサイズで書き出す**：表示サイズの2倍程度の解像度で書き出すだけで十分です。4,000px幅の画像をサムネイルに使うのは過剰です。
- **遅延読み込み（Lazy Load）の設定**：スクロールしないと見えない画像には`loading="lazy"`属性を付与することで、初期表示を速くできます。

### キャッシュとサーバーの設定

同じユーザーが再訪した際の表示速度を上げるには、ブラウザキャッシュの設定が有効です。WordPressを使用している場合は、**WP Super Cache**や**W3 Total Cache**といったプラグインで比較的簡単に設定できます。

また、レンタルサーバーの種類も速度に影響します。共有サーバーを利用している場合、表示速度に限界がある場合もあります。サーバー環境の見直しも選択肢に入れておきましょう。

### 不要なスクリプトの削減

WordPressサイトでは、プラグインの増加によってJavaScriptやCSSが肥大化しやすいです。使っていないプラグインは削除し、Google Tag Managerを使ってタグを一元管理することで、不要な読み込みを整理できます。

## クローラビリティを高めるサイト構造の整備

いくら良いコンテンツがあっても、Googleのクローラーにページが発見されなければ意味がありません。サイト構造の整備は「SEOの下地づくり」とも言える作業です。

### XMLサイトマップの作成と送信

XMLサイトマップは、サイト内のURLをまとめてGoogleに知らせるためのファイルです。WordPressであれば「Yoast SEO」や「Rank Math」プラグインで自動生成できます。生成したサイトマップはGoogle Search ConsoleのサイトマップメニューからURLを送信しておきましょう。

### robots.txtの確認

robots.txtは、クローラーにアクセスしてほしくないページを指定するファイルです。管理画面のURL、重複コンテンツが発生しやすいタグページなどをDisallow設定することで、クロール予算の無駄遣いを防げます。

ただし、設定ミスによってサイト全体がインデックスされなくなるリスクもあります。変更後は必ずSearch Consoleの「URLの検査」ツールで動作確認してください。

### 内部リンクの最適化

クローラーはリンクをたどってページを発見していきます。孤立したページ（どこからもリンクされていないページ）はインデックスされにくくなります。

- カテゴリページから個別記事へのリンクが適切に設置されているか
- 関連記事のリンクが本文内に設けられているか
- 重要なページへのリンクがサイト内の複数箇所から設置されているか

これらを定期的にチェックする習慣をつけましょう。

## 構造化データで検索結果をリッチに表示する

**構造化データ**とは、Googleに対してページの内容を機械的に伝えるためのコードです。適切に設定すると、検索結果に星評価・FAQ・パンくずリストなどの「リッチリザルト」が表示されるようになります。

クリック率（CTR）の向上につながるため、競合が多いキーワードでも差別化できる可能性があります。

### 主な構造化データの種類

| タイプ | 向いているサイト | 表示例 |
|---|---|---|
| FAQPage | すべてのサイト | Q&Aが検索結果に展開表示 |
| LocalBusiness | 店舗・クリニック等 | 営業時間・電話番号の強調 |
| Product | ECサイト | 価格・在庫・評価の表示 |
| Article | ブログ・メディア | 公開日・著者名の表示 |

### 実装方法の確認

構造化データはJSON-LD形式で記述するのが一般的です。WordPressであればプラグイン（Schema & Structured Data for WPなど）を使った実装も可能です。

実装後は**Googleのリッチリザルトテスト**（https://search.google.com/test/rich-results）でエラーがないか必ず検証してください。

## まとめ：テクニカルSEOは「土台」として整備する

本記事で取り上げた内容を整理します。

- **Core Web Vitalsの計測**：PageSpeed InsightsとSearch ConsoleでLCP・INP・CLSを確認する
- **サイト速度の改善**：画像最適化・キャッシュ設定・不要スクリプトの削減から手をつける
- **クローラビリティの整備**：XMLサイトマップの送信・robots.txtの確認・内部リンクの見直し
- **構造化データの実装**：FAQやLocalBusinessから着手し、リッチリザルト表示を狙う

テクニカルSEOは一度整えたら終わりではなく、定期的なモニタリングと改善が必要な継続作業です。まずはPageSpeed Insightsでの計測と、Search Consoleの「ウェブに関する主な指標」レポートの確認から始めてみてください。
