# AI検索のアクセスログ調査｜自社サイトへの巡回状況を確認する方法

ChatGPTやPerplexity、Googleの生成AI検索（AI Overviews）が普及するにつれて、「自分のサイトはAIに読まれているのか？」という疑問を持つ担当者が増えています。AIに情報源として認識されるためには、まずAIのクローラーやボットが自社サイトを巡回していることが前提になります。

ところが多くの企業では、AIクローラーの巡回状況を把握できていません。アクセスログを見る習慣がない、あるいはそもそもどこを見ればよいかわからない、というケースが大半です。この記事では、アクセスログを使ってAIクローラーの巡回状況を具体的に確認する方法を解説します。

---

## なぜ今、AIクローラーの巡回状況を把握する必要があるのか

従来のSEOでは、GooglebotやBingbotといった検索エンジンのクローラーが自サイトを巡回しているかを確認することが基本でした。AI検索が台頭した現在、それに加えてAI固有のクローラーへの対応が求められています。

代表的なAIクローラーとしては以下のものが挙げられます。

- **GPTBot**（OpenAI / ChatGPT）
- **Claude-Web**（Anthropic / Claude）
- **PerplexityBot**（Perplexity AI）
- **Applebot-Extended**（Apple Intelligence）
- **CCBot**（Common Crawl / 多くのAIの学習データに活用）

これらのボットがサイトに来訪しているかどうかを把握することで、「AIに情報として取得されているかの手がかり」が得られます。なお、巡回されているからといって必ずAIの回答に使われるわけではありませんが、巡回されていなければ情報源になる可能性はほぼありません。

---

## アクセスログの確認場所と取得方法

アクセスログとは、Webサーバーに記録されたすべてのアクセスの履歴ファイルです。誰（どのIPアドレス・ユーザーエージェント）がいつ、どのページにアクセスしたかが記録されています。

### ログの取得先

| 環境 | 確認方法 |
|------|----------|
| レンタルサーバー（エックスサーバーなど） | 管理画面の「アクセスログ」メニューからダウンロード |
| VPS・専用サーバー | SSH接続後に `/var/log/apache2/access.log` または `/var/log/nginx/access.log` を参照 |
| WordPress（プラグイン活用） | 「WP Security Audit Log」などで一部確認可能だが、ボット検出精度は低い |
| CDN利用（Cloudflareなど） | Cloudflareのダッシュボードのボットレポートで確認できる場合がある |

ログファイルの形式はサーバーによって異なりますが、一般的なApache形式では次のように記録されています。

```
123.45.67.89 - - [15/Jul/2025:10:23:41 +0900] "GET /blog/seo-tips/ HTTP/1.1" 200 4321 "-" "GPTBot/1.0 (+https://openai.com/gptbot)"
```

この中の**ユーザーエージェント（UA）文字列**がクローラーの識別に使えます。

---

## AIクローラーを特定するユーザーエージェント文字列の調べ方

ログの中からAIクローラーの記録を探すには、ユーザーエージェント文字列で絞り込みます。主要なAIクローラーのUA文字列は以下の通りです。

| クローラー名 | ユーザーエージェントに含まれる文字列 |
|------------|--------------------------------------|
| GPTBot | `GPTBot` |
| OAI-SearchBot（ChatGPT検索） | `OAI-SearchBot` |
| Claude-Web | `Claude-Web` または `anthropic-ai` |
| PerplexityBot | `PerplexityBot` |
| Applebot-Extended | `Applebot-Extended` |
| CCBot | `CCBot` |
| Bytespider（ByteDance） | `Bytespider` |

Linuxサーバーであればgrepコマンドで抽出が簡単です。

```bash
grep -i "GPTBot\|PerplexityBot\|Claude-Web\|anthropic-ai\|OAI-SearchBot" /var/log/nginx/access.log
```

このコマンドで、各AIクローラーの巡回履歴だけを一覧で確認できます。

## ログ分析で確認すべき5つのチェックポイント

ログを取得した後は、単に「来ているか・来ていないか」だけでなく、以下の観点で分析することが重要です。

### ① 巡回頻度と最終巡回日時

GPTBotなどが最後にいつ来訪したかを確認します。更新頻度の高いサイトほどクローラーが再訪しやすい傾向があります。長期間巡回されていない場合は、コンテンツの更新や内部リンクの整備が対策の手がかりになります。

### ② 巡回されているページの種類

どのURLが巡回されているかを見ると、AIクローラーがサイトのどの部分に関心を持っているかがわかります。重要なコンテンツページが巡回されていない場合は、`robots.txt`やサイトマップの設定を見直す余地があります。

### ③ HTTPステータスコード

巡回時に返しているステータスコードを確認します。

- `200`：正常に取得できている
- `301/302`：リダイレクトされている（最終URLまで追えているかを確認）
- `403`：アクセス拒否（`robots.txt`でブロックしている可能性）
- `404`：ページが存在しない（削除済みページへの巡回が起きている）

特に`403`が出ている場合、`robots.txt`の設定でAIクローラーを意図せずブロックしている可能性があります。

### ④ robots.txtによるブロック状況

AIクローラーの巡回を許可するかブロックするかは`robots.txt`で制御できます。意図せずブロックしているケースは意外と多く、次のような記述がある場合は注意が必要です。

```
User-agent: *
Disallow: /
```

これはすべてのボットをブロックする設定です。AIクローラーに巡回させたい場合は、特定のUAのみDisallowにするか、`robots.txt`自体を見直す必要があります。

### ⑤ 巡回されているがインデックスされていない可能性

ログ上は巡回されていても、ページ内に`noindex`タグや`X-Robots-Tag: noindex`が設定されていると、AIが情報として取得しない場合があります。技術的な巡回と情報の取得は別の概念として考えることが重要です。

---

## Google Search Consoleでの補足確認

サーバーログに直接アクセスできない環境では、Google Search Consoleを補助的に活用できます。ただし、Search ConsoleはGooglebotの情報のみを提供しており、GPTBotやPerplexityBotの巡回状況は確認できません。

とはいえ、GoogleのAI Overview（生成AI検索）に対応するという文脈では、Googlebotによる巡回とインデックス状況の確認は依然として重要です。「URL検査」ツールで主要ページのインデックス状況を確認し、クロールエラーがないかをチェックしておきましょう。

---

## まとめ｜ログ調査はAIO対策の出発点

AIに自社サイトの情報を参照してもらうためには、まずAIクローラーがサイトを巡回できる状態になっているかを確認することが最初のステップです。

今回紹介したポイントをまとめると以下の通りです。

1. **サーバーのアクセスログを取得し、AIクローラーのUAで絞り込む**
2. **巡回頻度・巡回ページ・ステータスコードを確認する**
3. **robots.txtで意図せずブロックしていないかを確認する**
4. **Google Search Consoleでクロールエラーがないかもチェックする**

ログ調査は一度だけでなく、定期的に実施することで変化を追うことができます。AIクローラーの種類や挙動は今後も変わる可能性があるため、継続的なモニタリングが求められます。
